## Signal probe, 2026-10-13

Samsung SM-A155M, Android 16, USB. `probe/` builds an observer app (normal permissions plus `QUERY_ALL_PACKAGES`, targetSdk 35) and a stub accessibility service. Four samples are in `probe/`. These are local developer builds, not a model or release acceptance.

With the ADB backend running, the observer saw `adb_enabled=1`, the USB state broadcast `adb=true`, `init.svc.adbd=running`, loopback port 19008 open, and the runner jar under `/data/local/tmp` (still present after disconnect). `AccessibilityManager.isEnabled()` was true with an empty enabled-service list. Injected taps came from device id -1 named `Virtual`, size 1.0, touch axes 0, two events per tap, exactly at the view centre. Text arrived as one `ACTION_SET_TEXT` accessibility action and one watcher replacement, with no input-connection or key events. The human sample on the same build came from device 5 `sec_touchscreen`, size about 0.018, touch axes 5/4, 3–11 events per tap, off-centre; keyboard text arrived as input-connection commits and key events. Pressure was 1.0 in both.

The stub service was enabled with `adb shell settings put secure enabled_accessibility_services` after `adb install` and bound without a restricted-settings prompt. `am force-stop` removed it from the enabled list; after `pm grant … WRITE_SECURE_SETTINGS` the stub re-added itself and bound again. While a UiAutomation runner was alive, the same setting was cleared or the service stayed unbound; it bound once the runner exited.

The stub then turned developer options and USB debugging off through `Settings.Global`, the observer collected unattended, and the stub restored both 15 s later; ADB returned without re-authorization. In that sample `adb_enabled=0`, `development_settings_enabled=0`, `init.svc.adbd=stopped`, `sys.usb.state=mtp`, the broadcast had no `adb` extra and no loopback port was open. The stub stayed in the enabled list, the observer could see its package and its `WRITE_SECURE_SETTINGS` grant, and the leftover runner jar was still visible.

## Accessibility backend, 2026-10-13

The Rust TLS/WebSocket companion and host were built from local source; this is development acceptance, not a published APK or CLI release. Samsung SM-A155M/Android 16 connected over Wi-Fi with developer options and USB debugging off. The normal-permission observer recorded both settings as 0, `adbd=stopped`, USB `mtp`, all scanned loopback ports closed and no leftover runner jar. Enabled accessibility services remained visible. See `accessibility/developer-off-signals.json`; unrelated installed-service inventory is excluded.

Eight synthetic native/password/offline-WebView input checks passed inside a 90-second developer-off window; completion was 57.878 seconds after the observer sample. Ten Settings→Connections→Bluetooth batches also passed within a separately checked developer-off window, median 3579.385 ms, with independently read postconditions and unchanged Bluetooth switch. Discovery correctly kept `settled=false`. Initial transition checks refused stale snapshots and off-display targets before sending input; a fresh stable read allowed the next attempt. Successful gestures were never replayed.

The on-phone screenshot API returned a valid PNG, inspected with Unicode WebView text and redacted synthetic password. Five CLI reconnects and five reconnects within one MCP process passed; host authorization stayed stable. Removing only the companion service from settings restored drivable status after 4256.01 ms, preserving the other enabled service. Android force-stop returned `phone_disconnected`; explicitly opening the app and starting its saved pairing recovered control. The in-app stop action disconnected and disabled only its own service. A different active lease owner was refused before dispatch.

This run does not establish behavior after hardware reboot, screen lock, Samsung deep sleep or manual installation without `WRITE_SECURE_SETTINGS`. Copy/paste pairing is implemented; QR scanning is not. The release workflow builds a checksum and requires a separate private signing key for tagged releases. No release was published. `acceptance.json` records the APK checksum and individual JSON files retain outcomes and timings. `probe/fixture/` contains the synthetic native/WebView app; `scripts/test-accessibility-input.py` reruns inputs without runtime ADB after that fixture has been installed.
